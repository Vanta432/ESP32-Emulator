# ESP32 Emulator

Небольшой desktop-эмулятор ESP32 на Rust с графическим интерфейсом. Приложение показывает виртуальную плату, которая выглядит как подключённый ESP32 с USB-UART, и запускает демонстрационную прошивку на наблюдаемом учебном ядре, похожем по модели регистров и периферии на Tensilica Xtensa LX6.

> Важно: это самостоятельный эмулятор и учебная модель, а не драйвер физического ESP32 и не полный бинарно-совместимый декодер Xtensa LX6. Физическая плата для запуска не нужна.

## Возможности

- тёмный графический интерфейс на `eframe/egui`;
- виртуальное подключение ESP32-WROOM-32 и USB-UART 115200 8N1;
- 16 регистров `a0..a15`, `PC`, `PS`, счётчик тактов и инструкций;
- учебное подмножество инструкций LX6: арифметика, переходы, GPIO, UART и SRAM;
- демо-прошивка, которая считает итерации, пишет счётчик в SRAM, переключает `GPIO0` и отправляет `LED toggled` в serial monitor;
- визуальные GPIO-светодиоды и виртуальная кнопка `BOOT` на `GPIO4`;
- вкладки `OVERVIEW`, `CPU / DEBUG`, `MEMORY`, `SERIAL MONITOR`;
- пошаговое выполнение, пауза, сброс, просмотр дизассемблированного учебного ROM и hexdump SRAM;
- кнопка **TURBO** и ползунок мощности от `1×` до `64×`;
- подключаемые виртуальные модули: OLED 128×64, LCD 1602, DHT22, WS2812 и buzzer;
- отдельная вкладка `MODULES` с превью экранов, показаниями датчика, RGB-светодиодами и состоянием звукового модуля;
- модули получают состояние GPIO и счётчик тактов CPU, а подключение и отключение отражается в виртуальном UART.

## Подключаемые модули

На боковой панели или во вкладке `MODULES` выберите тип устройства и нажмите `ATTACH MODULE`. Каждое нажатие создаёт отдельный экземпляр модуля. Поддерживаются:

| Модуль | Виртуальное подключение | Что видно в эмуляторе |
| --- | --- | --- |
| OLED 128×64 | I²C `0x3C` | экран с частотой, GPIO и счётчиком циклов |
| LCD 1602 | I²C `0x27` | двухстрочный символьный экран |
| DHT22 | single-wire sensor bus | детерминированные температура и влажность |
| WS2812 ×8 | GPIO / DATA | восемь RGB-пикселей, реагирующих на `GPIO0` |
| Active buzzer | GPIO | активность и частота тона от `GPIO0` |

Модуль можно временно отключить кнопкой `ENABLED`, удалить через `DETACH`, а после `RESET` подключённые устройства сохраняются и сбрасывают только своё состояние.

## Turbo и такты процессора

Базовая модель ESP32 работает с виртуальной частотой `240 MHz`. Для того чтобы GUI не зависал, эмулятор использует нормированный бюджет `240 000` виртуальных тактов в секунду при скорости `1×`; это не попытка измерить реальную частоту host-компьютера.

Когда включена кнопка **TURBO**, за один и тот же интервал времени эмулятор выдаёт ядру в `N` раз больше бюджета, где `N` — выбранный множитель мощности. Например:

- `1×` — обычная скорость ESP32;
- `8×` — за единицу времени выполняется в 8 раз больше тактов и прошивка продвигается в 8 раз быстрее;
- `64×` — максимальный множитель в интерфейсе.

В шапке окна это отражается как `240 × N MHz simulated`. На каждой инструкции учитывается стоимость такта: переходы, SRAM и UART занимают больше одного виртуального такта. Поэтому счётчик циклов остаётся осмысленным, а Turbo изменяет именно пропускную способность выполнения, а не только анимацию.

## Запуск

Нужен Rust toolchain с Cargo (стабильный Rust 1.78+):

```bash
cargo run --release
```

Для запуска тестов ядра и платы:

```bash
cargo test
```

На Linux могут понадобиться системные библиотеки для окна `eframe`/winit (обычно `libx11-dev`, `libwayland-dev`, `libxkbcommon-dev` и OpenGL-драйвер). На Windows и macOS достаточно стандартного Rust toolchain и зависимостей платформы.

## Управление

| Элемент | Действие |
| --- | --- |
| `RUN / PAUSE` | Запустить или остановить виртуальный CPU |
| `STEP` | Выполнить одну LX6-подобную инструкцию |
| `RESET` | Сбросить CPU, SRAM, GPIO и виртуальный UART |
| `TURBO` | Включить/выключить ускоренный бюджет тактов |
| `TURBO POWER` | Выбрать множитель от 1× до 64× |
| `BOOT BUTTON` | Изменить уровень входа `GPIO4` |
| `ATTACH MODULE` | Подключить выбранный виртуальный экран, датчик или исполнительный модуль |
| `ENABLED / DISABLED` | Временно включить или отключить модуль |
| `DETACH` | Удалить модуль из виртуальной платы |
| `SEND` в Serial Monitor | Отправить строку в виртуальный RX UART |

## Структура проекта

```text
.
├── Cargo.toml
├── README.md
└── src
    ├── board.rs    # виртуальная плата, GPIO, UART и бюджет выполнения

    ├── modules.rs  # подключаемые экраны, датчики и исполнительные модули
    └── main.rs     # окно eframe/egui и панели отладки
```

## Нужен ли `.gitignore`?

Да. Для Rust-проекта он нужен, чтобы не добавлять в Git каталог `target/`, временные файлы Cargo, настройки IDE и локальные логи. В репозитории `.gitignore` уже добавлен и также сохраняет C/C++-шаблоны из исходного проекта для нативных зависимостей.

`.gitignore` — это не язык программирования и его нельзя «написать на C++»: это обычный текстовый файл с шаблонами имён файлов. Поэтому корректный вариант — именно правила игнорирования, а не C++-код. `Cargo.lock` в этом приложении не игнорируется: для desktop-бинарника его полезно хранить, чтобы фиксировать версии зависимостей.
